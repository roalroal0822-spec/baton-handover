# 업무바통 (인수인계 도우미)

2026 공공 AI 대전환 챌린지 세션2 지정과제 · **과제① 업무바통(인수인계)** 출품작

전임자의 업무 폴더(한글·PDF·엑셀·워드·파워포인트·메일·메모가 섞여 있어도)를 통째로 넣으면, 담당업무(R&R)·연간 일정·연락망·진행 중인 현안을 **출처와 함께** 정리한 인수인계서 초안을 만들고, 전임자 검토를 거쳐 후임자의 질문 답변과 업무 매뉴얼까지 이어 주는 도구입니다.

## 접속 주소

실행하면 브라우저가 자동으로 열립니다. 열리지 않으면 **http://localhost:8101** 로 접속하세요.
(포트 변경: `python run.py --port 9000` 또는 `config.json`의 `port`)

## 실행 방법

필요한 것: Python 3.10 이상(3.10·3.11·3.13에서 구동 확인), 인터넷(처음 한 번 라이브러리 설치). 모델은 없어도 됩니다.

- **Windows**: `run.bat` 더블클릭 (처음 실행 때 실행 환경을 만들고 라이브러리를 설치한 뒤 시작)
- **macOS·Linux**: `./run.sh`
- **직접 실행**:
  ```
  pip install -r requirements.txt
  python run.py
  ```
- **실행 파일(.exe) 만들기(선택)**: Windows PC에서 `tools\build_exe.bat` 실행 → `dist\baton-handover\baton-handover.exe` (이 실행 파일 만들기는 Windows 환경에서 아직 시험하지 못했습니다)
- 종료: 실행 창에서 `Ctrl+C`

## 주요 기능

### 기본기능
- **폴더째 넣기**: 한글(hwpx·hwp), PDF, 엑셀, 워드, 파워포인트(pptx, 발표자 메모 포함), 메일(eml), 텍스트·CSV를 한 번에 읽습니다. 옛 형식 .ppt는 .pptx로 저장해 넣어야 합니다. 읽지 못한 파일은 이유와 함께 따로 보여 줍니다. 세 가지 넣는 방법: 파일·폴더 올리기, PC 폴더 경로 지정, 문서시스템 API 연계(시연용 가상 문서시스템 포함).
- **출처가 달린 인수인계서 초안**: 모든 항목에 파일 이름·위치(쪽·행·문단)가 붙고, 누르면 원문 앞뒤 내용을 바로 확인합니다.
- **전임자 검토·수정**: 표에서 바로 고치고, 항목 추가·삭제, 확인 완료 표시, 수정 이력이 남습니다.

### 선택기능(구동되는 수준으로 구현)
- **연간 업무 달력**: 자료에서 찾은 시기별 할 일(매월 반복 포함)을 달력으로 정리
- **분류·요약**: 자료를 공식 문서·메일·개인 메모로 나누고 R&R·연락망·현안으로 정리
- **누락·충돌·불확실 표시**: 문서끼리 날짜가 다른 일정(예: 착공일 10/27 ↔ 11/3), 바뀐 연락처, "~예정/아마" 같은 불확실 표현, 담당자 없는 현안 등을 '확인 필요'로 표시
- **후임자 질문 답변**: "11월에 할 일?", "정민재 연락처?" 같은 질문에 자료 근거와 함께 답변
- **후임자 맞춤 업무 매뉴얼**: 월별 할 일, 연락망, 현안, 용어 풀이를 담은 매뉴얼을 한글·워드·마크다운으로 내보내기
- **문서시스템 API 연계 구조**: 자료 넣는 부분을 어댑터로 분리(`core/sources.py`)

## 작동 방법 (시연 순서)

1. 실행하면 브라우저가 열립니다(`http://localhost:8101`).
2. **① 자료 넣기**에서 자료 넣는 방법을 "시연용 모의자료"로 고르고, 후임자 이름을 적은 뒤 "인수인계 초안 만들기"를 누릅니다(실제 업무 폴더는 끌어다 놓기·폴더 선택으로 넣습니다).
3. **② 인수인계 초안·검토**에서 담당업무·일정·연락처·현안을 확인합니다. 출처 칩을 누르면 원문 위치가 보입니다. 표 칸을 눌러 고치고 "확인 완료"를 누릅니다.
4. **연간 업무 달력**, **확인 필요**(충돌·누락·불확실) 탭을 봅니다.
5. **③ 후임자 질문**에 "11월에 할 일 알려줘", "정민재 연락처"처럼 물어봅니다.
6. **후임자 업무매뉴얼**에서 매뉴얼을 만들고 한글(HWPX)·워드로 내려받습니다. 인수인계서도 같은 방식으로 내려받습니다.

발표·영상용으로 장면별 화면 조작과 설명을 정리한 대본은 [시연대본.md](시연대본.md)에 있습니다.

## 모델(LLM) 연결과 교체

- 모델 없이도 모든 기능이 규칙 기반으로 동작합니다. 모델을 연결하면 문서마다 모델이 항목을 더 찾아 보태고(근거 위치가 실제 원문이 아니면 버림), 업무 개요와 질문 답변을 자연스러운 문장으로 다듬습니다.
- 화면 오른쪽 위 **모델 배지**를 누르거나 `config.json`(예시: `config.example.json`)에서 바꿉니다. 코드 수정은 필요 없습니다.
- 지원 방식
  - `openai`: OpenAI 호환 API(`/v1/chat/completions`) — 행정안전부 AI 공통기반, vLLM, Ollama(`/v1`), LM Studio 등
  - `ollama`: Ollama 기본 API(`/api/chat`)
- 모델 설정 화면에서 **빠른 설정**(내 PC의 Ollama / AI 공통기반·vLLM)과 **모델 계열**을 고르고, **모델 목록 불러오기**로 서버에 실제 등록된 모델 이름을 받아 고를 수 있습니다.

### 행정안전부 AI 공통기반 지원(예정) 모델 연결

| 모델 계열 | 연결 방법 | 계열별 차이 처리(자동) |
|---|---|---|
| 젬마(Gemma, Google) | OpenAI 호환 또는 Ollama 예: `gemma3:4b` | system 역할을 받지 않는 서버면 지시문을 첫 질문에 합쳐 다시 요청 |
| 라마(Llama, Meta) | OpenAI 호환 또는 Ollama 예: `llama3.1:8b` | 없음(표준 형식) |
| GPT-OSS (OpenAI 공개 모델) | OpenAI 호환 또는 Ollama 예: `gpt-oss:20b` | 추론형: 토큰 한도를 늘리고, 생각만 하다 답이 비면 한도를 키워 다시 요청 |
| 엑사원(EXAONE, LG AI연구원) | OpenAI 호환 또는 Ollama 예: `exaone3.5:7.8b` | 답 앞의 생각 과정 태그(`<thought>`, `<think>`) 제거 |
| 하이퍼클로바X(HyperCLOVA X, 네이버) | OpenAI 호환(AI 공통기반·vLLM 등) | 생각 과정 태그 제거 |
| 솔라(Solar, 업스테이지) | OpenAI 호환 또는 Ollama 예: `solar-pro` | 없음(표준 형식) |

- 공통: JSON 출력 형식 지정(`response_format`)을 지원하지 않는 서버면 형식 지정 없이 다시 요청하고, 답에 섞인 설명·코드 블록을 걷어 내고 JSON만 읽습니다.
- 위 Ollama 이름은 예시입니다. AI 공통기반의 실제 주소와 모델 이름은 기관에서 안내받은 값을 쓰거나 **모델 목록 불러오기**로 확인하세요.
- 앱 코드는 `chat()`·`json()` 두 함수만 쓰므로 새 모델 계열이 추가돼도 앱 코드는 바뀌지 않습니다(`core/llm.py`의 `FAMILIES`에 한 줄 추가).
- 환경변수로도 바꿀 수 있습니다: `LLM_PROVIDER`, `LLM_BASE_URL`, `LLM_MODEL`. API 키는 파일에 적지 않고 환경변수(기본 `LLM_API_KEY`)로만 읽습니다.
- 예) Ollama: `ollama pull gemma3:4b` 후 연결 방식 `openai`, 주소 `http://localhost:11434/v1`, 모델 `gemma3:4b`
- 모델이 낸 결과는 그대로 쓰지 않고 원문과 대조해 검증합니다(근거 위치·현행 조문에 실제로 있는지). 검증에 걸린 제안은 버리고 그 사실을 화면에 표시합니다. 모델 호출이 실패하면 규칙 기반 결과로 계속 진행합니다.

### 2종 이상 모델 검증 방법

- Windows: [Ollama](https://ollama.com/download)를 설치한 뒤 `모델검증.bat`을 더블클릭하면 젬마(`gemma3:4b`)와 엑사원(`exaone3.5:2.4b`)을 내려받아 주요 기능을 차례로 돌리고 `verify_report.md`를 만듭니다. 다른 모델은 `모델검증.bat llama3.1:8b gpt-oss:20b`처럼 이름을 붙여 실행합니다.
  - 모델 파일은 기본으로 C 드라이브(사용자 폴더 `.ollama`)에 저장됩니다. 다른 드라이브에 두려면 환경변수 `OLLAMA_MODELS`를 그 폴더로 지정하고 Ollama를 다시 시작하세요.
- 직접 실행:
```
python tools/verify_models.py --base-url http://localhost:11434/v1 --models gemma3:4b exaone3.5:2.4b
```
모델별·기능별 통과 여부와 걸린 시간을 `verify_report.md`로 남깁니다. `--mock`을 붙이면 가짜 모델 서버로 연결 경로와 계열별 응답 차이 처리(system 역할 거부, 생각 과정 태그, 추론형 빈 답)만 시험합니다(실제 모델 성능 검증이 아님).

> 현재 상태: 개발 환경에서는 실제 모델을 내려받을 수 없어 가짜 모델 서버로만 확인했습니다(5종 흉내, 전 항목 통과). 실제 모델 2종 검증은 `모델검증.bat`으로 실행해 보고서를 함께 제출하는 것을 권장합니다.

## 자료 사용과 원본 보호

- 함께 넣은 `sample_data/`는 가상의 **공공기관** 기준으로 지어낸 모의자료입니다. 실제 기관·인물·연락처와 관계없습니다. (`tools/samples_baton.py`로 다시 만들 수 있습니다)
- 투입한 원본 파일은 읽기만 합니다. 폴더 경로로 넣으면 그 폴더를 읽기만 하고, 올린 파일은 작업 폴더에 사본으로 보관합니다.
- 작업 데이터와 산출물은 `data/` 폴더(설정 `data_dir` 또는 환경변수 `APP_DATA_DIR`로 변경)에만 저장합니다. 데이터베이스 설치가 필요 없습니다.

## 폴더 구조

```
run.py              실행 진입점 (브라우저 자동 열림)

engine.py           기능 로직
qa.py               기능 로직
report.py           기능 로직
static/             화면(HTML·JS, 외부 라이브러리 없음)
core/               공통 모듈: 문서 읽기(hwpx·hwp·docx·pptx·pdf·xlsx·eml·txt), 검색, 모델 연결, 문서 내보내기(hwpx·docx·md), 저장소, 웹 서버
sample_data/        모의자료
tools/              모델 검증 도구, 가짜 모델 서버, 모의자료 생성기
tests/              구동 점검
data/               작업 데이터·산출물 (실행 시 생성, 저장소에 올리지 않음)
```

## 정식 활용(정보화사업) 이관 메모

- 파이썬 표준 라이브러리 웹 서버 + 바닐라 JS로 만들어 외부 프레임워크 의존이 적습니다. 기능 로직(`engine.py, qa.py, report.py`)은 웹 계층과 분리되어 있어 다른 프레임워크로 옮기기 쉽습니다.
- 바꾸기 쉬운 연결 지점: 저장소(`core/store.py`, JSON 파일 → DB), 모델(`core/llm.py`, 설정만으로 교체), 문서 읽기(`core/loaders.py`), 문서 내보내기(`core/export.py`), 자료 넣는 곳(`core/sources.py`: 폴더·업로드·문서시스템 API 어댑터)
- 로그인·권한은 시연 범위에서 단순화했습니다(정식 구축 시 기관 인증 연동 필요).

## 알려진 한계

- 한글 HWP(5.0) 파일은 본문 글자만 읽으며, 실제 HWP 파일로는 시험하지 못했습니다(HWPX는 시험함). 표·그림 속 글자는 빠질 수 있습니다.
- 스캔한 PDF(그림)는 글자를 읽지 못합니다(OCR 미포함).
- 규칙 기반 추출은 공공기관 문서에서 흔한 표현을 기준으로 만들었습니다. 기관마다 표현이 다르면 일부 항목을 놓칠 수 있어 전임자 검토 단계를 둡니다.
