# 업무바통 (인수인계 도우미)

2026 공공 AI 대전환 챌린지 세션2 지정과제 · **과제① 업무바통(인수인계)** 출품작

전임자의 업무 폴더(한글·PDF·엑셀·워드·파워포인트·메일·메모가 섞여 있어도)를 통째로 넣으면, 담당업무(R&R)·연간 일정·연락망·진행 중인 현안을 **출처와 함께** 정리한 인수인계서 초안을 만들고, 전임자 검토를 거쳐 후임자의 질문 답변과 업무 매뉴얼까지 이어 주는 도구입니다.

## 접속 주소

실행하면 브라우저가 자동으로 열립니다. 열리지 않으면 **http://localhost:8101** 로 접속하세요.
(포트 변경: `python run.py --port 9000` 또는 `config.json`의 `port`)

## 실행 방법

필요한 것: Python 3.10 이상(3.10·3.11·3.13에서 구동 확인), 인터넷(처음 한 번 라이브러리 설치). 모델은 없어도 됩니다.

- **Windows**: `run.bat` 더블클릭 (처음 실행 때 실행 환경을 만들고 라이브러리를 설치한 뒤 시작)
- **macOS·Linux**: `./run.sh`
- **직접 실행**:
  ```
  pip install -r requirements.txt
  python run.py
  ```
- **실행 파일(.exe) 만들기(선택)**: Windows PC에서 `tools\build_exe.bat` 실행 → `dist\baton-handover\baton-handover.exe` (이 실행 파일 만들기는 Windows 환경에서 아직 시험하지 못했습니다)
- 종료: 실행 창에서 `Ctrl+C`

## 주요 기능

### 기본기능
- **올인원 드롭존**: 종류 구분 없이 몽땅 끌어다 놓으면 됩니다(시작 화면 어디에 놓아도 받고, 여러 번 놓으면 쌓이며, 같은 파일은 한 번만 담고, 다른 곳에서 온 같은 이름 파일은 이름을 나눠 보관). 담은 파일은 엑셀 2·한글 1·메모장 3처럼 종류별로 보여 줍니다. 한글(hwpx·hwp), PDF, 엑셀, 워드, 파워포인트(pptx, 발표자 메모 포함), 메일(eml), 텍스트·CSV를 한 번에 읽습니다. 옛 형식 .ppt는 .pptx로 저장해 넣어야 합니다. 읽지 못한 파일은 이유와 함께 따로 보여 줍니다. 세 가지 넣는 방법: 파일·폴더 올리기, PC 폴더 경로 지정, 문서시스템 API 연계(시연용 가상 문서시스템 포함).
- **출처가 달린 인수인계서 초안**: 모든 항목에 파일 이름·위치(쪽·행·문단)가 붙고, 누르면 원문 앞뒤 내용을 바로 확인합니다.
- **전임자 검토·수정**: 표에서 바로 고치고, 항목 추가·삭제, 확인 완료 표시, 수정 이력이 남습니다.

### 선택기능(구동되는 수준으로 구현)
- **연간 업무 달력**: 자료에서 찾은 시기별 할 일(매월 반복 포함)을 달력으로 정리
- **분류·요약**: 자료를 공식 문서·메일·개인 메모로 나누고 R&R·연락망·현안으로 정리
- **누락·충돌·불확실 표시**: 문서끼리 날짜가 다른 일정(예: 착공일 10/27 ↔ 11/3), 바뀐 연락처, "~예정/아마" 같은 불확실 표현, 담당자 없는 현안 등을 '빈틈 스캐너'로 표시
- **'시한폭탄 방지' D-Day 리스크 레이더**: 인수인계 자료의 기한(일정·현안·계약 만료)과 **공공기관 법정·행정 주기**(상반기 재정 신속집행 점검 4월·마감 6월, 의회 행정사무감사 D-60 준비, 다음 연도 예산안 의회 제출(지방자치법 제142조), 회계연도 마감·이월 점검, 결산(제150조), 해빙기·여름/겨울철 자연재난대책기간)를 **후임자 착임(발령)일 기준**으로 한 줄에 세웁니다. '③ D-Day 리스크 레이더' 탭 맨 위에 붉은 타임라인 카드 두 묶음을 둡니다.
  - **[부임 첫 주에 해야 할 일]**: 착임 후 7일 안 기한과 이미 지난 기한(처리됐는지 확인)
  - **[이번 달 미체결 시 감사 지적 우려 계약]**: 착임 후 30일 안에 걸린 입찰공고·재계약·착공·보험 갱신. 계약 대장의 연간 용역·임차는 **만료 60일 전 다음 계약 착수일**을 따로 세우고(이미 지났으면 '착수 권장일 지남'), 착공·준공·갱신은 위험 이유(변경계약·지체상금·보장 공백 등)를 함께 적습니다. 풀리지 않은 '빈틈 스캐너'(충돌·불확실)가 걸린 카드는 경고를 붙입니다.
  - '③ D-Day 리스크 레이더' 탭에서 착임일·의회 행정사무감사 달·기관 유형(시·군·구/시·도/공공기관)을 바꾸면 다시 계산하고, 앞으로 120일 타임라인(자료 + 공공 주기, 법령 링크·준비 요령 포함)과 '일이 생기면 시작되는 법정 기한'(조례 공포: 이송받은 날부터 20일 이내(지방자치법 제32조), 민원 법정 처리기간)을 보여 줍니다. 인수인계서·후임자 매뉴얼 첫머리에도 들어갑니다.
  - 공공 주기는 일반적인 법정·행정 일정이라 기관·의회마다 날짜가 다를 수 있어 화면·문서에 '기관 일정 확인'을 함께 적습니다.
- **공공기관 특화 휴먼 네트워크 맵(암묵지 시각화)**: 담당 업무(가운데) ─ 세부 업무 ─ 협업 상대를 노드 그래프로 그립니다. 협업 상대는 **우리 팀·기관 내 협업 부서(예산·계약·총무)·외부 기관·의회(전문위원실)·업체·반복 민원**으로 나누고, 사람 이름 대신 역할('경영지원팀 주임', '(주)그린공조 팀장')로만 적습니다. 원을 누르면 연락처·'이럴 때 연락'·노하우 카드가 나옵니다.
  - **노하우 카드**: 자료 속 "결재 전에 경영지원팀과 사전 협의 필수", "그린공조는 마감 3일 전 재확인", "같은 민원인이 반복 제기, 회신 전 팀장 보고" 같은 실무 요령 문장을 찾아 사전 협의·재확인·주의·요령 카드로 만들어 해당 협업 상대에 붙입니다. 전임자가 직접 카드를 쓸 수 있고(사람 이름을 적어도 역할로 바뀌어 저장), 맞지 않는 자동 카드는 숨깁니다. 인수인계서 '협업 네트워크와 노하우' 장과 바통 파일에 들어가 다음 세대로 이어집니다.
- **포토 아카이브**: 넣은 자료 속 사진(JPG·PNG 등, ZIP 안 사진 포함)만 따로 모아 보고, '직무중심교육', '주차장 균열', '9월'처럼 키워드로 관련 사진을 찾습니다. 단서는 파일·폴더 이름, 사진 속 글자(현수막·안내문·화이트보드, OCR), AI 사진 설명(이미지를 볼 수 있는 모델을 연결했을 때), 찍은 날짜(EXIF), 같은 폴더의 다른 자료, 이 사진을 근거로 한 인수인계 항목이며, 사진마다 왜 찾았는지 표시합니다. AI 분신에게 물으면 답 아래에 관련 사진이 함께 나옵니다. 사진은 긴 변 1,024px로 줄인 사본만 보관하고 위치 정보(EXIF)는 지우며, 사진 속 얼굴·이름표는 자동으로 가리지 않으므로 화면에서 지울 수 있습니다.
- **AI 전임자 분신**: 전임자 자료·노하우·앞 세대 질의응답만 근거로 1인칭으로 답하고(답마다 출처), 자료에 없는 질문은 지어내지 않고 **물어볼 협업 상대(역할·연락처)**를 휴먼 네트워크에서 찾아 알려 줍니다. (전임자가 답변을 남기는 별도 창구는 두지 않습니다. 확인한 내용은 ② 표나 노하우 카드에 남기면 AI 분신이 근거로 씁니다.)
- **표준 인수인계서(필수 5대 영역) + 법령 검색 API**: '⑥ 표준 인수인계서' 탭에서 공공기관 인수인계서 필수 5대 영역을 표준 입력 폼으로 작성합니다. ① 담당 사무 개요 및 근거 법령 ② 주요 추진 업무 및 연간 일정 ③ 예산 및 계약 현황(조달·계약) ④ 미결 과제 및 유의 사항 ⑤ 보관 문서 및 주요 연락처. 넣은 자료로 먼저 채워 두므로(예산·계약 표, 자료에 나온 법령 이름 등) 확인·수정만 하면 되고, 고치면 자동 저장되며 한글(HWPX)·워드 서식(서명란 포함)으로 내려받습니다.
  - **법령 검색**: 국가법령정보 공동활용 Open API(law.go.kr DRF)로 법령·행정규칙·자치법규를 이름으로 찾아 조문을 골라 넣습니다. 넣은 조문은 '법령정보 확인·시행일'로, 자료에서 이름만 찾은 법령은 '자료 기재(확인 전)'로 구분되고 '조문 찾기' 한 번으로 바꿀 수 있습니다. 받은 결과는 1주일간 저장해 두어 같은 법령은 다시 받지 않고, 인터넷이 끊기면 저장본을 씁니다.
  - **인증값(OC)**: open.law.go.kr에서 'Open API 활용 신청' 후 받은 아이디(보통 신청 이메일의 @ 앞부분)를 화면에 넣거나 환경변수 `LAW_OC`로 설정합니다. 기관 PC는 방화벽에서 `www.law.go.kr` 접속이 허용돼야 합니다.
- **뒤죽박죽 자료도 그대로(개떡같이 넘겨도 찰떡같이)**: 전임자가 최소한의 파일만 아무렇게나 모아 올려도 정리해서 읽습니다.
  - 휴대폰 사진(JPG·PNG 등)과 스캔한 PDF는 글자 인식(OCR)으로 읽습니다. 쓸 수 있는 방법을 차례로 시도합니다: **Tesseract**(설치돼 있으면) → **Windows 기본 OCR**(Windows 10·11, 한국어 언어팩이 있으면 추가 설치·인터넷 없이) → **비전 모델**(연결한 모델이 이미지를 볼 수 있으면, 예: gemma3). 사진에서 읽은 내용은 '사진에서 읽은 글자에만 있어 원본 확인 필요'로 표시하고, 글자를 못 읽은 사진은 버리지 않고 '빈틈 스캐너'에 올립니다. 찍은 날짜(EXIF)도 기록합니다.
  - ZIP은 풀어서 읽고(두 단계까지, 한국어 Windows 압축의 한글 파일 이름 처리, 300MB·3,000개 상한), 같은 내용 파일(복사본)·빈 파일·임시/시스템 파일은 빼며, 옛 형식(.xls·.doc·.ppt·.heic·RAR 등)은 바꾸는 방법을 안내합니다. 정리 결과는 '자료 목록'에 이유별로 묶어 보여 줍니다.
  - 제목 줄이 엉망인 엑셀, '진행상황' 열이 없는 표의 비고("재계약 검토 필요")에서도 현안을 찾습니다.
- **인수인계 충실도 점검**: 인수인계서에 꼭 있어야 할 7개 영역(담당 업무·연간 일정·진행 중 현안·협의 연락망·근거 규정·예산·계약·시스템/자료 위치)마다 자료가 충분·부족·없음인지 근거와 함께 판정합니다. 모자란 영역은 **인계 면담 질문지**로 묶어 보여 주고(복사 가능), 면담에서 들은 내용은 표나 노하우 카드에 남깁니다. 인수인계서 첫 장에도 점검표가 들어갑니다.
- **인수인계 순서도**: 자료 모으기 → AI 초안 → 전임자 검토 → 빈틈 스캐너 → 확인 완료 → AI 분신 질의 → 바통 넘기기 7단계를 이 인수인계 건의 실제 진행 상태(✓ 완료·▶ 진행 중·○ 예정)와 근거 숫자(검토한 항목 수, 남은 빈틈 등), '지금 할 일'과 함께 보여 줍니다. 화면에서는 단계를 누르면 해당 화면으로 가고, 인수인계서(한글·워드·마크다운) 첫머리에 표 형태 순서도로 들어갑니다. 후임자 업무매뉴얼에는 '착임 후 순서도(첫날 → 첫 주 → 첫 달 → 1년)'가 들어갑니다.
- **지식 릴레이(바통 파일, .baton)**: 검토한 인수인계서를 `.baton` 파일로 저장해 다음 담당자에게 넘깁니다. 다음 인수인계 때 자료에 함께 넣으면 항목(근거·처음 기록된 세대 포함)·질의응답·노하우·메모·담당자 계보(사람 이름 대신 'n대 담당자')가 이어져 1대 → 2대 → 3대로 기관의 업무 지식이 쌓입니다. 앞 세대 현안이 이번 자료에 없으면 '지금도 진행 중인지' 확인 필요로 표시합니다.
- **내 일정으로 내보내기(.ics)**: 연간 업무 달력을 iCalendar 파일로 내보내 Outlook·그룹웨어 일정에 바로 넣습니다. 매월 업무는 매월, 정기 업무는 달마다 매년 반복으로 들어가고 알림(매월 업무 하루 전, 나머지 일주일 전)이 붙습니다. 착임일 전에 지난 기한은 '기한 지남'으로 빼고, 날짜(일)가 없으면 초 5일·중순 15일·말 말일(그 밖에는 1일, 착임한 달이면 착임일)에 넣어 제목에 '(날짜 확인)'을, 확인이 안 된 일정은 '[빈틈]'를 붙입니다.
- **후임자 맞춤 업무 매뉴얼**: 착임일 기준 리스크 레이더, 월별 할 일, 협업 상대, 현안, 용어 풀이를 담은 매뉴얼을 한글·워드·마크다운으로 내보내기
- **문서시스템 API 연계 구조**: 자료 넣는 부분을 어댑터로 분리(`core/sources.py`)

## 과제 카드·심사 기준 대응표

## 작동 방법 (시연 순서)

1. 실행하면 브라우저가 열립니다(`http://localhost:8101`).
2. **① 올인원 드롭존**에 업무 자료를 종류 구분 없이 몽땅 끌어다 놓습니다(엑셀·한글·PDF·워드·메일·메모장·사진·ZIP·바통 파일, 폴더째도 가능, 여러 번 나눠 놓으면 쌓임). 후임자 착임(발령)일을 고르고 "인수인계 초안 만들기"를 누릅니다. 시연할 때는 드롭존 아래 "파일 없이 시작하기 → 시연용 모의자료"를 고릅니다. 이름은 입력받지 않습니다.
3. **③ D-Day 리스크 레이더**에서 붉은 카드(부임 첫 주·이번 달 계약)와 120일 타임라인·공공 주기를, **④ 휴먼 네트워크**에서 협업 상대와 노하우 카드를 봅니다.
4. **②**에서 담당업무·일정·연락처·현안을 확인합니다. 출처 칩을 누르면 원문 위치가 보입니다. 표 칸을 눌러 고치고 "확인 완료"를 누릅니다. **연간 업무 달력**, **빈틈 스캐너**(자료끼리 다름·빠진 정보·애매한 내용·기한 지남) 탭도 봅니다.
5. **⑤ AI 전임자 분신**에 "11월에 할 일 알려줘", "승강기 업체 연락처"처럼 물어봅니다. "체육센터 대관료 감면 기준은?"처럼 자료에 없는 질문은 지어내지 않고 물어볼 협업 상대를 알려 줍니다.
6. **후임자 업무매뉴얼**에서 매뉴얼을 만들고 한글(HWPX)·워드로 내려받습니다. 인수인계서도 같은 방식으로 내려받습니다.
7. **연간 업무 달력**에서 "내 일정으로 내보내기(.ics)", ② 화면에서 "바통 파일로 저장(.baton)"을 누릅니다. 받은 `.baton`을 다른 자료와 함께 새로 넣으면 3대 인수인계가 됩니다.

발표·영상용으로 장면별 화면 조작과 설명을 정리한 대본은 [시연대본.md](시연대본.md)에 있습니다.

## 모델(LLM) 연결과 교체

- 모델 없이도 모든 기능이 규칙 기반으로 동작합니다. 모델을 연결하면 문서마다 모델이 항목을 더 찾아 보태고(근거 위치가 실제 원문이 아니면 버림), 업무 개요와 질문 답변을 자연스러운 문장으로 다듬습니다.
- 화면 오른쪽 위 **모델 배지**를 누르거나 `config.json`(예시: `config.example.json`)에서 바꿉니다. 코드 수정은 필요 없습니다.
- 지원 방식
  - `openai`: OpenAI 호환 API(`/v1/chat/completions`) — 행정안전부 AI 공통기반, vLLM, Ollama(`/v1`), LM Studio 등
  - `ollama`: Ollama 기본 API(`/api/chat`)
- 모델 설정 화면에서 **빠른 설정**(내 PC의 Ollama / AI 공통기반·vLLM)과 **모델 계열**을 고르고, **모델 목록 불러오기**로 서버에 실제 등록된 모델 이름을 받아 고를 수 있습니다.

### 행정안전부 AI 공통기반 지원(예정) 모델 연결

| 모델 계열 | 연결 방법 | 계열별 차이 처리(자동) |
|---|---|---|
| 젬마(Gemma, Google) | OpenAI 호환 또는 Ollama 예: `gemma3:4b` | system 역할을 받지 않는 서버면 지시문을 첫 질문에 합쳐 다시 요청 |
| 라마(Llama, Meta) | OpenAI 호환 또는 Ollama 예: `llama3.1:8b` | 없음(표준 형식) |
| GPT-OSS (OpenAI 공개 모델) | OpenAI 호환 또는 Ollama 예: `gpt-oss:20b` | 추론형: 토큰 한도를 늘리고, 생각만 하다 답이 비면 한도를 키워 다시 요청 |
| 엑사원(EXAONE, LG AI연구원) | OpenAI 호환 또는 Ollama 예: `exaone3.5:7.8b` | 답 앞의 생각 과정 태그(`<thought>`, `<think>`) 제거 |
| 하이퍼클로바X(HyperCLOVA X, 네이버) | OpenAI 호환(AI 공통기반·vLLM 등) | 생각 과정 태그 제거 |
| 솔라(Solar, 업스테이지) | OpenAI 호환 또는 Ollama 예: `solar-pro` | 없음(표준 형식) |

- 공통: JSON 출력 형식 지정(`response_format`)을 지원하지 않는 서버면 형식 지정 없이 다시 요청하고, 답에 섞인 설명·코드 블록을 걷어 내고 JSON만 읽습니다.
- 위 Ollama 이름은 예시입니다. AI 공통기반의 실제 주소와 모델 이름은 기관에서 안내받은 값을 쓰거나 **모델 목록 불러오기**로 확인하세요.
- 앱 코드는 `chat()`·`json()` 두 함수만 쓰므로 새 모델 계열이 추가돼도 앱 코드는 바뀌지 않습니다(`core/llm.py`의 `FAMILIES`에 한 줄 추가).
- 환경변수로도 바꿀 수 있습니다: `LLM_PROVIDER`, `LLM_BASE_URL`, `LLM_MODEL`. API 키는 파일에 적지 않고 환경변수(기본 `LLM_API_KEY`)로만 읽습니다.
- 예) Ollama: `ollama pull gemma3:4b` 후 연결 방식 `openai`, 주소 `http://localhost:11434/v1`, 모델 `gemma3:4b`
- 모델이 낸 결과는 그대로 쓰지 않고 원문과 대조해 검증합니다(근거 위치·현행 조문에 실제로 있는지). 검증에 걸린 제안은 버리고 그 사실을 화면에 표시합니다. 모델 호출이 실패하면 규칙 기반 결과로 계속 진행합니다.

### 2종 이상 모델 검증 방법

- Windows: [Ollama](https://ollama.com/download)를 설치한 뒤 `모델검증.bat`을 더블클릭하면 젬마(`gemma3:4b`)와 엑사원(`exaone3.5:2.4b`)을 내려받아 주요 기능을 차례로 돌리고 `verify_report.md`를 만듭니다. 다른 모델은 `모델검증.bat llama3.1:8b gpt-oss:20b`처럼 이름을 붙여 실행합니다.
  - 모델 파일은 기본으로 C 드라이브(사용자 폴더 `.ollama`)에 저장됩니다. 다른 드라이브에 두려면 환경변수 `OLLAMA_MODELS`를 그 폴더로 지정하고 Ollama를 다시 시작하세요.
- 직접 실행:
```
python tools/verify_models.py --base-url http://localhost:11434/v1 --models gemma3:4b exaone3.5:2.4b
```
모델별·기능별 통과 여부와 걸린 시간을 `verify_report.md`로 남깁니다. `--mock`을 붙이면 가짜 모델 서버로 연결 경로와 계열별 응답 차이 처리(system 역할 거부, 생각 과정 태그, 추론형 빈 답)만 시험합니다(실제 모델 성능 검증이 아님).

> 현재 상태: 개발 환경에서는 실제 모델을 내려받을 수 없어 가짜 모델 서버로만 확인했습니다(5종 흉내, 전 항목 통과). 실제 모델 2종 검증은 `모델검증.bat`으로 실행해 보고서를 함께 제출하는 것을 권장합니다.

## 자료 사용과 원본 보호

- 모의자료 폴더의 `00_이전인수인계/시설운영_1대_인계.baton`은 1대 담당자가 2024년에 2대 담당자에게 넘긴 바통 파일(지식 릴레이 시연용)입니다.
- `sample_data/전임자_뒤죽박죽_최소자료/`는 최소한의 자료를 아무렇게나 모은 경우(휴대폰 사진·스캔 PDF·엉망인 엑셀·한글·ZIP·복사본·빈 파일·옛 형식)를 흉내 낸 모의자료입니다. 화면의 '모의자료(뒤죽박죽 최소자료)'로 써 볼 수 있습니다.
- 함께 넣은 `sample_data/`는 가상의 **공공기관** 기준으로 지어낸 모의자료입니다. 실제 기관·인물·연락처와 관계없습니다. (`tools/samples_baton.py`로 다시 만들 수 있습니다)
- 투입한 원본 파일은 읽기만 합니다. 폴더 경로로 넣으면 그 폴더를 읽기만 하고, 올린 파일은 읽은 뒤 작업 사본을 지웁니다(이름이 든 원문을 남기지 않음).
- **사람 이름 비식별(항상 켜짐)**: 자료를 읽는 즉시 사람 이름을 역할 이름으로 바꿔 저장합니다(전임자·후임자, 앞 세대는 'n대 담당자', 연락처는 '계약팀 주임'·'(주)그린공조 팀장'처럼 소속·직위, 그 밖에 문장 속 사람은 '관계 주무관 1'). 휴대전화는 가운데 자리(010-****-9081), 개인 메일은 앞부분(***@기관.kr)을 가리고 부서 공용 메일은 그대로 둡니다. 화면·AI 답·인수인계서(한글·워드)·바통 파일·저장 데이터 어디에도 실제 이름이 남지 않으며, 올린 원본 사본도 읽은 뒤 지웁니다. 나중에 사람이 적는 메모·노하우·서식도 같은 규칙으로 바뀝니다(이름 자체는 저장하지 않고 되돌릴 수 없는 해시만 보관). 전임자·후임자 이름은 입력받지 않습니다. 모의자료 원본 파일에는 이 기능을 보여 주기 위한 가상 인물 이름이 들어 있습니다.
- 작업 데이터와 산출물은 `data/` 폴더(설정 `data_dir` 또는 환경변수 `APP_DATA_DIR`로 변경)에만 저장합니다. 데이터베이스 설치가 필요 없습니다.

## 정식 활용(정보화사업) 이관 메모

- 파이썬 표준 라이브러리 웹 서버 + 바닐라 JS로 만들어 외부 프레임워크 의존이 적습니다. 기능 로직(`engine.py, qa.py, report.py`)은 웹 계층과 분리되어 있어 다른 프레임워크로 옮기기 쉽습니다.
- 바꾸기 쉬운 연결 지점: 저장소(`core/store.py`, JSON 파일 → DB), 모델(`core/llm.py`, 설정만으로 교체), 문서 읽기(`core/loaders.py`), 문서 내보내기(`core/export.py`), 자료 넣는 곳(`core/sources.py`: 폴더·업로드·문서시스템 API 어댑터)
- 로그인·권한은 시연 범위에서 단순화했습니다(정식 구축 시 기관 인증 연동 필요).
- 보안: 화면은 `localhost` 또는 IP 주소로 접속한 요청만 받고(DNS 리바인딩 차단), 다른 웹사이트에서 보낸 요청은 거부합니다. 모델 API 키는 `LLM_`·`OPENAI_` 등으로 시작하는 환경변수 이름만 쓸 수 있어 다른 비밀값이 모델 서버로 나가지 않습니다.

| lxml | python-hwpx 의존 | BSD-3-Clause |

## 알려진 한계

- 한글 HWP(5.0) 파일은 본문 글자만 읽으며, 실제 HWP 파일로는 시험하지 못했습니다(HWPX는 시험함). 표·그림 속 글자는 빠질 수 있습니다.
- 법령 검색 API는 개발 환경의 네트워크 정책상 law.go.kr에 접속할 수 없어, 실제 서버가 아니라 공개 명세의 응답 모양을 흉내 낸 시험 서버로만 확인했습니다. 인증값(OC)을 받아 기관 PC에서 한 번 확인이 필요하며, 응답 모양이 다르면 `core/lawapi.py`만 고치면 됩니다.
- 사진·스캔본 글자 읽기는 PC에 Tesseract가 있거나, Windows 10·11 기본 OCR(한국어 언어팩)이 있거나, 이미지를 보는 모델을 연결해야 동작합니다. 셋 다 없으면 사진은 '글자를 읽지 못함'으로 표시만 됩니다. Windows 기본 OCR 연결 코드는 개발 환경(리눅스)에서 실제로 돌려 보지 못했으므로 기관 PC에서 확인이 필요합니다(비전 모델 경로는 가짜 모델 서버로 확인). 손글씨는 인식률이 낮을 수 있습니다.
- 규칙 기반 추출은 공공기관 문서에서 흔한 표현을 기준으로 만들었습니다. 기관마다 표현이 다르면 일부 항목을 놓칠 수 있어 전임자 검토 단계를 둡니다.
